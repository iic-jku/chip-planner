# Chip View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One `Chip` tab with pads, IO ring, real core, macros and flylines, plus pad-order help, analog/RF and power checks, placement helpers, undo/redo and a LibreLane `MACROS` export.

**Architecture:** All analysis and edits are pure functions in a new `model/chip.py` working on a `Project` and its `Layout`; `formats/librelane.py` gains `macros_yaml`; the GUI (`gui/chip_view.py`, `gui/macro_panel.py`, `gui/main_window.py`) only draws, forwards mouse actions to model edits and keeps an undo stack of project snapshots.

**Tech Stack:** Python ≥ 3.9 stdlib, PySide6/PyQt6 via `gui/qt.py`, unittest.

**Spec:** `docs/superpowers/specs/2026-11-02-chip-view-design.md`

## Global Constraints

- No Qt in `model/`, `formats/`, `style.py`, `cli.py`, `__init__.py`.
- µm everywhere, y down, origin top-left of the die (model); LibreLane output uses origin lower-left.
- Project files stay readable: new JSON keys optional, `tests/data/layout_baseline.json` unchanged.
- English UI and code; palette from `style.py`; numbers with decimal point.
- Tests: `python3 -m unittest discover -s tests -t .`.
- Every edit that changes editor text is a model function and one undo step in the GUI.

## Review Focus

1. Dragging a pad that is part of a grouped line (`RFIN [gsg]`) or a split line → the whole line moves, nothing duplicates. (Task 3 `test_move_group_line`, `test_move_split_line`.)
2. A side with spacer lines (empty lines) → drop index and adjacency use the real slots; spacers stay. (Task 3 `test_move_keeps_spacers`; Task 2 `test_spacer_breaks_adjacency`.)
3. Project without splits → every macro and pad is in domain `""`; supply checks still work. (Task 2 `test_supply_without_splits`.)
4. Macro bigger than the core area or no macros at all → no crash, flylines empty, warnings sensible. (Task 2 `test_no_macros`.)
5. Undo after `Add missing pads` restores the editors and the floorplan exactly. (Task 6 `test_undo_add_missing_pads`.)

### Task 2: Chip analysis (`model/chip.py`)

**Files:** Create `src/chip_planner/model/chip.py`; Test `tests/test_chip.py` (new; reuse the LEF fixture).

**Interfaces — Produces:**
- `@dataclass Flyline: instance: str, pin: str, pad: str, side: str, line: int, p: Tuple[float,float], q: Tuple[float,float], length: float, sensitive: bool, crossing: bool = False`. `q` = inner ring edge point of the pad (`T: (cx, ring_depth)`, `B: (cx, die_h − ring_depth)`, `L: (ring_depth, cy)`, `R: (die_w − ring_depth, cy)` from the `Pin`). - `@dataclass MissingPin: instance: str, pin: str, name: str, side: str, pos: float, function: Optional[str], p, q` (q on the inner ring edge of the nearest side; pos along the side, physical order).
- `@dataclass SupplySuggestion: instance: str, name: str, function: str ("vdd"|"vss"), side: str, index: int` (insert index in physical order of that side).
- `@dataclass ChipCheck: flylines: List[Flyline], missing: List[MissingPin], crossings: int, longest: Optional[Flyline], supplies: List[SupplySuggestion], warnings: List[str]`.
- `analyse(project, layout=None) -> ChipCheck` (layout computed if None).
- Helpers used by later tasks: `pad_domain(layout) -> Dict[str, str]` (pin tag → domain), `diff_partner(name) -> Optional[str]` (final `P`↔`N`, keeps the rest), `pad_class(...)` per spec.

### Task 4: LibreLane MACROS export

**Files:** Modify `src/chip_planner/formats/librelane.py`; Test `tests/test_pdk.py`.

**Interfaces — Produces:** `macros_yaml(project, layout, out_dir=None, source="") -> str`; `librelane_files(project, source="", out_dir=None)` adds `"macros.yaml"` when the project has non-placeholder macros; `export_librelane` passes its directory; `chip_core_template_sv` appends a comment block `// Macros (place with these instance names, see macros.yaml):` listing `<macro> <instance>` lines when macros exist.

Format (exact):
```yaml
# <header>
MACROS:
  adc_sar_top:
    gds: [dir::<rel>/final/gds/adc_sar_top.gds]
    lef: [dir::<rel>/final/lef/adc_sar_top.lef]
    instances:
      i_chip_core.adc0:
        location: [160, 870]
        orientation: N
```
`<rel>` = macro path relative to `out_dir` (absolute path without `out_dir`); location = lower-left of the placed macro, die coordinates, origin lower-left (`x = x0 + m.x`, `y = die_h − (y0 + m.y + h)`), numbers `:g`; orientation `{0: N, 90: E, 180: S, 270: W}`; placeholders as `# placeholder <name> (no LEF) not exported`.
